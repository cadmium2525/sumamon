## 1. 直したいこと

本家では、復帰が難しいキャラでも
**「中央へ向けて空中回避 → 2段ジャンプ → 上B」**で戻ってこられる。
本作ではこの手順が成立しないどころか、**空中回避を挟むと復帰が短くなる**。

### 実測（Version 1.50・コスモ・既定ステータス）

崖の外側へ置き、空中ジャンプ1回残り（＝地上から吹き飛ばされた直後の状態）から
復帰できた限界距離。

| 手順 | 横の限界 | 崖より下から戻れる深さ |
|---|---|---|
| 2段ジャンプのみ | 260px | — |
| 上Bのみ | 120px | — |
| **2段ジャンプ → 上B** | **640px** | **500px** |
| **空中回避 → 2段ジャンプ → 上B** | **580px** | **180px** |
| 空中回避のみ | 20px | — |

**空中回避を挟むと、横が 640→580、深さが 500→180 に減る。**
本家では復帰を伸ばす手段なので、真逆になっている。

### 空中回避1回の実測

| 項目 | 実測値 |
|---|---|
| 操作不能フレーム | **61** |
| 横に進んだ距離 | **121px** |
| その間に落ちた距離 | **314px** |
| 終了時の落下速度 | 6.3（最大落下速度に到達済み） |
| ジャンプは残るか | 残る ✓ |
| 上Bは残るか | 残る ✓ |
| helpless になるか | ならない ✓ |

**横に121px進む間に314px落ちる。** これでは復帰に使えない。
なお「回避後に行動できる」「helpless にならない」は本家どおりで、ここは正しい。

## 2. 本家SPでの挙動（合わせる先）

- 方向を入れた空中回避は、**入力方向へ滑るように移動する**。
  移動している間は落下がほぼ止まるため、**高度を失わずに距離を稼げる**。
- 回避後は行動できる（helpless にならない）。**2段ジャンプ・上Bへ繋げられる**。
- 空中回避は**1回の滞空につき1回**。着地または**崖つかまり**で回復する。
- 連続で使うと弱くなる（無敵が短くなる）。

つまり本家の空中回避は「無敵で避ける技」であると同時に**「復帰距離を伸ばす移動技」**。
本作は前者だけが実装されていて、後者が機能していない。

---

## 3. 原因（コードの該当箇所）

### 原因1: 空中回避中の横速度に「吹っ飛びの減速」がかかっている

`js/fighter.js` `update()`（1477行付近）

```js
const controllable = this.hitstun <= 0 && this.landingLag <= 0 && !this.downed &&
  !this.tumbling && this.dazedTimer <= 0 && this.dodgeTimer <= 0;
if (!controllable) {
  ...
  // 空中：毎フレーム KNOCKBACK_DECEL(0.17) ずつ横速度を削る
}
```

`dodgeTimer <= 0` が条件に入っているため、**空中回避中が「吹っ飛び中」と同じ扱い**になる。
`AIR_DODGE_SPEED` は 6.5 だが、0.17/フレームで削られて **約38フレームで停止**し、
移動距離は 6.5² / (2×0.17) ≒ **124px** にしかならない（実測121pxと一致）。

空中回避の移動は吹っ飛びではなく**技による移動**なので、この減速の対象から外す必要がある。

### 原因2: 空中回避中も重力が全開でかかる

`js/physics.js` `applyGravity()` は `update()` から無条件で呼ばれる。
そのため61フレームの間ずっと落下が加速し、**314px落ちる**。
本家の滑空に相当する処理が無い。

### 原因3: 操作不能が61フレームと長い

`js/config.js`

```js
DODGE_TABLE: {
  airDir: { total: 61, inv: [4, 20] },   // 方向入力あり
},
```

約1秒間なにもできない。落ちながら1秒待つので、
上の原因2と合わさって「使うと落ちる技」になっている。

### 原因4: 崖つかまりで空中回避が回復しない

`js/fighter.js` `grabLedge()`（686行付近）は
`jumpsUsed = 0` と `_usedUpSpecialAirborne = false` は戻すが、
**`_airDodgeUsed` を戻していない**。本家では崖つかまりで空中回避も回復する。

## 4. 修正方針

### 4-1. 空中回避の移動を「吹っ飛び」扱いから外す（原因1）

`controllable` の判定から空中回避を除外する。ただし**その場回避・転がりは今のまま**にすること
（あちらは地上の技で、横に飛んでいく必要がない）。

```js
// 空中回避の移動は技による移動であって吹っ飛びではない。
// 吹っ飛び用の減速をかけると、6.5で出しても38フレームで止まり
// 120pxしか進まない＝復帰に使えない技になる。
const controllable = ... && (this.dodgeTimer <= 0 || this.dodgeType === 'air');
```

### 4-2. 滑空フェーズを作る（原因2）

方向を入れた空中回避に「滑空する区間」を設け、**その間は重力を止める**。
区間を抜けたら通常の落下に戻す。

- 新しい定数 `AIR_DODGE_GLIDE_FRAMES`（滑空フレーム数）を `js/config.js` に追加
- `Physics.applyGravity` の呼び出しを、滑空中だけ飛ばす

### 4-3. 【重要】滑空の終わりに横速度を落とす

**ここを忘れると新しい自滅が生まれる。**
試作で確認済みの罠で、4-1と4-2だけを入れると、
滑空が終わった瞬間に**横速度6.5のまま落下を始める**ため、
**台の下へ潜り込んでそのまま死ぬ**（試作時、空中回避のみの復帰限界が 20px → 180px に伸びた一方、
空中回避→2段ジャンプ→上B の深さ限界は 180px → **0px** に悪化した）。

滑空区間の終わりで横速度を減衰させること（例：滑空終了時に一定割合まで落とす、
または滑空後の区間だけ通常の空気抵抗を効かせる）。

### 4-4. 総フレームを短くする（原因3）

`DODGE_TABLE.airDir.total` を短縮する。無敵の窓 `inv: [4, 20]` は変えないこと
（無敵時間はバランスに直結し、今回の目的とは別の話）。

### 4-5. 崖つかまりで空中回避を回復させる（原因4）

`grabLedge()` に `this._airDodgeUsed = false;` を追加する。

## 5. 目標値（この数字で合否を判定する）

すべて**コスモ・既定ステータス・空中ジャンプ1回残り**で測ること。
測り方は「§7 検証方法」に記載。

| 指標 | 現在 | 目標 |
|---|---|---|
| 空中回避→2段ジャンプ→上B の**横**限界 | 580px | **800px 以上**（かつ 2段ジャンプ→上B より長いこと） |
| 同、**深さ**限界 | 180px | **650px 以上**（かつ 2段ジャンプ→上B より深いこと） |
| 空中回避1回の横移動距離 | 121px | **落下距離より大きいこと** |
| 空中回避1回の落下距離 | 314px | **150px 以下** |
| 空中回避の操作不能フレーム | 61 | **40以下** |

**必ず守る条件（変えてはいけないもの）**

- 2段ジャンプ→上B 単体の限界（横640px・深さ500px）を**下げない**
- 空中回避は**1回の滞空につき1回**のまま（着地・崖つかまりで回復）
- 空中回避後に **helpless にならない**（2段ジャンプ・上Bへ繋がる）
- **無敵の窓 `inv: [4, 20]` を変えない**
- 上必殺は空中で1回のまま

## 6. 実装時の注意

1. **その場回避・転がりに影響を出さないこと。** 4-1の除外は `dodgeType === 'air'` に限定する。
   ここを広く取ると、転がりが止まらなくなる。
2. **滑空後の横速度**を必ず落とす(§4-3)。台の下へ潜り込む自滅が新たに生まれる。
3. **方向入力なしの空中回避（`air`）は移動しない技**。滑空処理を適用しないこと。
   `_airDodgeDirectional` で判別できる。
4. **`AIR_DODGE_LANDING_LAG`（着地硬直10F）はそのまま。** 崖際で回避を擦る択を抑えるために入れてある。
5. **CPUへの影響を必ず確認すること。** CPUは `_recoveryIntent` で復帰するが、
   空中回避は使わない。復帰性能が変わると、直近で入れた「追撃しすぎない」判定
   （`js/cpu-ai.js` の `_pursuitLimit`、実測値に基づく）とズレる可能性がある。
   §7の回帰項目に入れてある。

## 7. 検証方法

Playwright（`serviceWorkers: 'block'`）で、リポジトリ直下に静的サーバを立てて実行する。

### 復帰限界の測り方

1. `Stage.load('cosmo')`。主足場は `Stage.platforms[0]`（x=250, w=900 → 崖は250と1150）
2. ブラストラインは `{ left:-420, right:1820, top:-420, bottom:1420 }`
3. ファイターを崖の外 `out` px、足場と同じ高さ（`y = MAIN.y - f.h`）に置く
4. **`f.jumpsUsed = 1` にする**（地上から吹き飛ばされた直後＝地上ジャンプ枠は消費済み）
   これを 0 にすると本来あり得ない2回ジャンプで測ってしまう
5. ステージ方向へ入力を入れ続けながら、手順どおりに入力する
6. 判定は**位置ではなく `f.falls` で行う**。`update()` は場外で自動的に中央へ
   復帰させるため、位置で見ると「戻れた」と誤判定する（過去に踏んだ罠）
7. `out` を20pxずつ増やし、戻れなくなる直前の値を限界とする
8. 深さは `y = MAIN.y - f.h + depth` として同様に測る（横は崖の外120px固定）

### 必須テスト

**目標の達成**
1. 空中回避→2段ジャンプ→上B の横限界が **800px 以上**
2. 同、深さ限界が **650px 以上**
3. どちらも「2段ジャンプ→上B」単体を**上回る**こと
4. 空中回避1回の落下距離が **150px 以下**、横移動が落下より大きい
5. 空中回避の操作不能フレームが **40以下**

**壊していないこと**
6. 2段ジャンプ→上B 単体が 横640px・深さ500px を**下回らない**
7. 空中回避は滞空1回につき1回（2回目は出ない）
8. **崖つかまりで空中回避が回復する**（4-5の確認）
9. 空中回避後に helpless にならず、2段ジャンプと上Bが出せる
10. その場回避・転がりの移動距離と総フレームが**変わっていない**
11. 空中回避を使った復帰で**台の下へ潜り込んで自滅しない**（§4-3の罠）

**回帰**
12. CPUの自滅が増えていないこと。
    段位戦の相手を想定した条件（相手が崖の外で停止・レベル4/7/9/10）で
    **自滅0のまま**であること
13. 既存テスト17本すべて成功（`test-phase1`〜`5`、`test-regress`、`test-all`、
    `test-review`、`test-ledgelock`、`test-rank`、`test-justshield`、
    修行コース5種、`test-map`）
14. ページ内JSエラーが0件

## 8. 過去に踏んだ落とし穴

1. **`update()` は場外で自動的に復帰（リスポーン）させる。**
   位置で生死を判定すると全部「生還」になる。必ず `falls` で見る。
2. **`jumpsUsed` の初期値。** 吹き飛ばされた状態を再現するなら 1。
   0 にすると空中で2回跳べてしまい、実機より甘い数字が出る。
3. **足元の位置。** `y = MAIN.y - f.h` にしないと足場にめり込んで接地しない。
   `MAIN.y - 60` のような決め打ちだと、体格によっては最初から落下する。
4. **`?v=` の上げ忘れ**とリリース4点セットの片手落ち。
5. 依頼者と同じバージョン番号を取ったら rebase して +1。**force push はしない。**

## 9. 進め方

1. §4-1（吹っ飛び減速から除外）→ 空中回避1回の横移動距離を実測

3. **§4-3（滑空後の減速）→ 台の下へ潜り込まないことを実測**（ここが山場）
4. §4-4（総フレーム短縮）・§4-5（崖つかまりで回復）
5. §5の目標値をすべて満たすまで定数を調整

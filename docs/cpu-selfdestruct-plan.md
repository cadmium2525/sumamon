# 高ステータスCPUがステージ端で自滅する問題 — 修正計画書

段位戦のSランク昇格戦・四大大会・レジェンド杯のように**ステータスの高いCPU**が、
プレイヤーがステージの端にいるだけで場外へ飛び出して自滅する。
原因は実際のバトルでフレーム単位まで特定済み。この文書のとおりに直してほしい。

---

- `main` へ直接コミット・プッシュする（ブランチもPRも作らない）
- リリース時は `service-worker.js` の `CACHE_NAME`・`version.json`・
  `index.html` のバージョン表記・更新履歴の4点をセットで更新する
- 変更したJS/CSSは `index.html` の `?v=` を1つ上げる
- コメントもコミットメッセージも日本語
- push が弾かれたら **force push はせず** `git fetch` して rebase。
  バージョン番号は相手の番号+1、更新履歴は両方残す

### 先に読んでほしい失敗例（同じ穴に落ちないために）

Version 1.52 で一度この問題の修正を入れ、**効果が無かったので1.53で取り下げている**。
失敗の理由は2つあって、どちらも「直し方」ではなく「調べ方」の問題だった。

1. **簡易ハーネスの結果を実ゲームの原因として扱った。**
   `new Fighter(...)` を直接生成して回すテストは、**当たり判定が無く、
   キャラ固有の落下速度・ジャンプ力も渡っていない**（`buildFighterOptions` を
   通していない）。そこで再現した挙動は実際のバトルでは起きていなかった。
2. **計測指標にバグがあり、正しい仮説を自分で棄却した。**
   「技を出したまま崖を越えた回数」を
   `onGround && attackTimer > 0` で数えていたため、**空中で出した技を1件も
   拾えず**、修正前後どちらも0件と出ていた。実際の原因は空中の技だった。

→ **§4の検証手順を必ず守ること。** 簡易ハーネスの数字を根拠にしない。

## 1. 原因（実測）

四大大会 MoB（マスターズ・オブ・ブリーディング／ライフ900・防御900・回避620）、
CPUレベル9、プレイヤーはステージ左端に立たせたまま。
実際の `startBattle` を通した対戦で取ったトレース（seed 55）：

| フレーム | 状態 |
|---|---|
| f76–92 | 台の上空285px、**空中ジャンプ残り0**で滞空。まだ場内（崖の77px内側） |
| f93 | 外向きへ vx **-10.16** で加速（空中最高速ほぼいっぱい） |
| f97 | **空中で通常必殺を出す。** この時点ではまだ場内（崖の26px内側） |
| f97–117 | **技中は vx が -10.1 に固定されたまま。** f100で崖を越え、186pxまで運ばれる |
| f118–120 | 後隙10フレーム。まだ -10.1 のまま、207pxへ |
| f335 | 623px外・上必殺使用済・helpless → 落下 |

### なぜ止まらないのか

`js/fighter.js:537` の移動処理は `if (this.attackTimer <= 0 && !inJumpSquat)` で
囲まれている。つまり**技の最中は左右の入力が一切反映されず、`vx` は
出した瞬間の値のまま保持される**。地上では摩擦もかからない
（`js/fighter.js:1487` の `controllable` に `attackTimer` が入っていないため）。

さらに `js/fighter.js:416` で `applyInput` は `recoveryTimer > 0` のとき
**即 return する**ので、後隙の間も一切操作できない。
`dodgeTimer > 0`（`:418`）、`hitstun > 0`（`:415`）も同じ。

CPU側の `_keepOnStage`（`js/cpu-ai.js:198`）は、空中分岐（`:228`以降）で
**左右の入力を消すだけ**なので、技の最中はまったく効かない。

### 定量（実バトル・乱数固定・5条件×8シード×各60秒）

| 崖越え | うち技/後隙が続いていた | うち空中で出した技 | 自滅 |
|---|---|---|---|
| 2 | **2** | **2** | **2** |

**場外へ出たのは全部「空中で技を出した勢いのまま」で、出た回は全部そのまま落ちている。**
条件を変えても、崖越えが起きるのはこのパターンだけだった。

## 2. 直すこと

### 修正1（本命）— 空中で「戻れなくなる技」を出させない

`js/cpu-ai.js` の `_keepOnStage`（`:198`）の**空中分岐**に、技の禁止を追加する。
1.52では地上分岐にだけ入れて空振りしたので、**必ず空中側に入れること。**

考え方は「この技が終わるまで今の速度で運ばれたら、戻れる範囲を超えるか」。
既にある `_pursuitLimit()`（`:179`）と、`:237` 付近の制動距離の計算を流用する。

```js
// 技を出すと、その全体フレーム＋後隙の間ずっと今の速度のまま運ばれる
// （attackTimer中は移動入力が効かず、recoveryTimer中は applyInput が
//  丸ごと入力を捨てるため）。崖の外へ向かう勢いが乗ったまま空中で技を出すと、
//  止める手段が無いまま戻れない距離まで運ばれる。実測では、崖の26px内側で
//  空中の通常必殺を出したCPUが207pxまで運ばれ、そのまま落ちていた。
const vx = self.vx || 0;
if (input.attack || input.special || input.grab) {
  const carried = cx + vx * CPUController.ATTACK_COMMIT_FRAMES;
  const outAfter = Math.max(stage.x - carried, carried - (stage.x + stage.w));
  if (outAfter > limit) {
    input.attack = false;
    input.special = false;
    input.grab = false;
  }
}
```

```js
// 技を出してから移動の入力が効くようになるまでのフレーム数（後隙込みの見込み）。
// 実測した空中の通常必殺が全体21F＋後隙10F。少し余裕を持たせる。
static ATTACK_COMMIT_FRAMES = 30;
```

**注意点**
- `limit` は `_pursuitLimit()` の戻り値。`:237` で既に計算しているので順番に気をつける
- **上必殺（復帰）を潰さないこと。** `_recoveryIntent`（`:496`）は
  `_keepOnStage` を通らない設計なので、この追加は復帰に影響しない。
  この前提を崩す変更（`_recoveryIntent` を `_keepOnStage` に通すなど）はしないこと
- 内向きに動いている時（`vx` が場内を向いている）は `outAfter` が小さくなるので
  自然に許可される。**崖際でも、場内へ向かっていれば技は出せる**

### 修正2（本家準拠）— 地上の動作中は崖から落ちない

スマブラSPでは**地上の行動中に崖から滑り落ちることはない**。
ダッシュ攻撃も転がり（横回避）も崖の縁で止まる。
このゲームは技の間ずっと等速で滑るため、**回避900のモンスターは332px滑る**
（ダッシュ11.07px/フレーム × 全体30フレーム）。ステージ端から確実に出る距離。

**これはCPU専用の問題ではない。** 育てたマスモンで崖際にダッシュ攻撃を振ると
プレイヤーも同じように滑って落ちる。本家準拠として直す。

`js/fighter.js` の `Physics.resolvePlatformCollision(this, platforms);`
（`:1524`）の直後で、次の条件をすべて満たす時に位置を足場の内側へ留める。

- `this.onGround` が真
- **止められない地上動作の最中**：
  `attackTimer > 0 || recoveryTimer > 0 || landingLag > 0 ||
   (dodgeTimer > 0 && dodgeType !== 'air')`
- **吹っ飛ばされてはいない**：`hitstun <= 0 && !tumbling && !downed`
  （被弾して吹っ飛んでいる時に崖で止まるのは本家と違う。ここは必ず除外する）

留め方は「体の中心が、今立っている足場の左右からはみ出さない」。
`groundedPlatform`（`js/physics.js:119` の `resolvePlatformCollision` が
設定している足場のインデックス）を使い、**メイン足場ではなく実際に立っている
足場**で判定すること。穴で分割された地面や浮遊足場でも正しく効かせるため。

留めた時は `vx = 0` にする（滑り続ける原因を消す）。

**やってはいけないこと**
- 走って崖から飛び出す動き自体は塞がない（本家でもできる。復帰阻止に必要）
- 空中には一切適用しない
- 吹っ飛び中に適用しない

**確認してほしい副作用**
- `js/practice.js` の修行ステージ（マンディー砂漠・パパス雪山など）で、
  地形の端をまたぐ動きが必要な場面が壊れていないか。
  過去にマンディー砂漠が別件で破損したことがあるので、5コースとも通しで見ること

### 修正3 — 操作が効かない間は復帰の手持ちを使わない

`js/cpu-ai.js` の `_recoveryIntent`（`:496`）。
`self.helpless` の早期returnの**直後**に、次を入れる。

```js
// 技・後隙・回避・のけぞりの間は applyInput が入力を丸ごと捨てるため、
// ここで空中ジャンプや上必殺を「使ったこと」にしても、高さや無敵だけ
// 消費して外向きの勢いは残る。特に上必殺を出すと helpless になり、
// まだ跳べたはずの高さから落ちるだけになる。
// 何も使わず、内側を入れたまま操作が戻るのを待つ。
if (self.attackTimer > 0 || self.recoveryTimer > 0 || self.landingLag > 0 ||
    self.dodgeTimer > 0 || self.hitstun > 0 || self.shieldDropLag > 0) {
  input.left = toward < 0; input.right = toward > 0; input.stickX = toward;
  return input;
}
```

**ここが一番間違えやすい。** この判定を「空中ジャンプの条件」（`:515`）に
`&&` で足すだけにすると、条件が偽になった時に**下の上必殺の分岐まで進んでしまい、
操作が効かない状態で上必殺を出して helpless になる**。1.52で実際にこれをやって
自滅が0回→12回に増えた。必ず**早期returnで打ち切る**こと。

## 3. 入れない案（検討済み・悪化を確認）

**空中加速度 `AIR_ACCEL` を回避ステータスでスケールさせる案は入れないこと。**

回避で最高速度は最大3.6倍になるのに `CONFIG.AIR_ACCEL`（`js/config.js:139`）は
0.18固定なので、育てるほど空中で自分の勢いを止められなくなる（回避900だと
停止まで61フレーム・340px）。理屈は通っているが、**実装して測ったら悪化した**
（同一条件で自滅11回 vs 7回）。制動が速くなる代わりに外向きにも速く加速して
しまうため。プレイヤーの操作感にも影響する話なので、今回は触らない。

## 4. 検証手順（ここが本題。必ずこのとおりに）

### 4-1. 簡易ハーネスで判断しない

`new Fighter(...)` を直接生成して回すテストは、**当たり判定が無く、
キャラ固有の落下速度・ジャンプ力も渡っていない**ので、実ゲームと挙動が違う。
1.52はこれで原因を取り違えた。**必ず `window.startBattle(...)` を通して測ること。**

### 4-2. 実バトルを回すための手順

`players` は `js/game.js` のモジュール変数で `window` から見えないため、
`Fighter.prototype.update` をフックして拾う。Playwrightは
`serviceWorkers: 'block'` で起動する。

```js
// 5倍速（1フレームあたり最大5ステップ進むので実時間の1/5で済む）
const on = performance.now.bind(performance); const t0 = on();
performance.now = () => t0 + (on() - t0) * 5;

// 乱数を固定して修正前後を同じ条件で比べる
window.__seed = s => { let a = s >>> 0; Math.random = () => {
  a |= 0; a = (a + 0x6D2B79F5) | 0;
  let t = Math.imul(a ^ (a >>> 15), 1 | a);
  t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296; }; };

// 参加ファイターを拾う（フックは一度だけ入れ、以後外さない。
// 外すと2回目以降の計測が空になる）
window.__seen = [];
const orig = Fighter.prototype.update;
Fighter.prototype.update = function (...a) {
  const res = orig.apply(this, a);
  if (!window.__seen.includes(this)) window.__seen.push(this);
  /* ここで計測 */
  return res;
};

AppFlow.showScreen('battle');            // これを呼ばないとループが回らない
window.startBattle({
  stageKey: LEGEND.stageKey, mode: 'cpu', cpuMode: 'normal',
  p1Key: 'irumine', p2Key: LEGEND.fighterKey, cpuLevel: 10,
  statOverrides: { cpu: { ...LEGEND.stats } },   // キーは cpu1 ではなく cpu
  cpuFighters: [{ fighterKey: LEGEND.fighterKey, masmonId: null }],
});
window.setBattleInputLocked(false);      // カウントダウンの入力ロックを外す
```

プレイヤー役は `setInterval` でステージ端に固定し、
`stocks` を大きくして試合が終わらないようにする。
`invincible` を立てて技を空振りさせる条件も用意すること（この条件で問題が出た）。

### 4-3. 測る指標

自滅は発生がまれで乱数のブレに埋もれるため、**原因そのものを数える**。

| 指標 | 定義 |
|---|---|
| 崖越え | 中心Xが足場の左右を初めて越えた回数 |
| **技中に崖越え** | 越えた時点で `attackTimer > 0 \|\| recoveryTimer > 0` だった回数 |
| 自滅 | `falls` の増加 |
| 技発生 | `attackTimer` が0から正へ変わった回数 |

**「技中に崖越え」を `onGround` で絞らないこと。** 1.52ではここで絞ったせいで
空中の技を1件も拾えず、修正前後どちらも0件と出て判断を誤った。

**技発生は必ず測ること。** 崖際で技を控えるようにする修正なので、
**CPUが弱腰になっていないか**の確認が要る。修正前と比べて大きく減っていたら
`ATTACK_COMMIT_FRAMES` が過剰なので下げる。

### 4-4. 合格ライン

修正前と修正後を、**同一シード8個以上**・5条件以上・各60秒（シミュレーション時間）で比較する。
条件は 四大大会4種＋レジェンド杯から選び、プレイヤーは「端で密着」「端でガード」
「端で無敵」の3通りを含めること。

- **技中に崖越え：0 になること**（今は2／同条件）
- **自滅：0 になること**（今は2／同条件）
- **技発生：修正前の9割以上を保つこと**（弱腰になっていない確認）
- 通常のCPU戦（レベル1〜9・既定ステータス）で自滅が増えていないこと

**修正前の数値も必ず自分で取り直すこと。** この文書の数値をそのまま比較対象に
しないこと（環境やシードが違えば変わる）。`git worktree add` で修正前の
コミットを別ディレクトリに出し、別ポートで配信して同じ計測スクリプトを
両方に当てるのが手軽。

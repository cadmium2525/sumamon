# 上必殺後（しりもち落下）に横移動が一切できない問題 — 修正計画書（第3弾）

レジェンド杯の実機動画で、**CPUが0%のまま7秒かけて場外へ流れ続け、
一度も戻ろうとせずに落ちる**挙動が確認された。
5cb532d までの修正（空中の能動的な減速・空中最高速度0.5・崖際の技の抑制）は
入っているが、この経路は塞がっていない。

原因は**CPUの判断ではなく物理側**にある。

## 1. 動画で起きていること

- プレイヤー（1P・106%）はステージ上で棒立ち
- CPU（デュラハン・**0%**）はステージ上空から左へ流れていく
- **7秒間、一度も内側へ戻ろうとしない。** 高度もほとんど変わらないまま
  真横に流れ続け、そのまま画面外へ消える
- CPUは0%＝**一度も攻撃を受けていない**。吹っ飛ばされたのではなく、
  完全に自分だけで場外へ出て落ちている

---

## 2. 原因 — helpless 中は入力が全部捨てられ、空気抵抗すら効かない

`js/fighter.js:436-440`：

```js
// 行動不能（上B使用後など）：着地するまで一切の操作を受け付けない
if (this.helpless) {
  if (!this.onGround) return;
  this.helpless = false;
}
```

`applyInput` がここで **return** するため、helpless の間は

- 左右の入力が効かない（横方向の制御が完全にゼロ）
- **`AIR_FRICTION`（0.994）による減速も効かない**
  （空気抵抗は同じ `applyInput` の中の移動処理にあるため、
  return で丸ごと飛ばされる）

つまり**上必殺を出した瞬間の横速度が、着地するか死ぬまで一切変わらない**。

### 実測（回避900・コスモ・崖の外150px）

| 状態 | 内側を入力し続けた結果 |
|---|---|
| 通常の空中 | 60フレームで **+250px**（速度5.53） |
| **helpless** | 60フレームで **0px**（速度0） |
| **helpless・外向き速度-3で内側入力** | 120フレームで **-360px**（速度は-3のまま1ミリも変わらない） |

3行目が動画そのもの。**外向きの速度を持ったまま上必殺を出したら、
どれだけ内側を入れても等速で場外へ運ばれて確実に死ぬ。**
高度がほとんど変わらないのは、上必殺の上昇が終わったあと
落下速度が終端まで上がる前の区間を、真横に等速で流れているため。

### 本家との違い

スマブラSPの**しりもち落下（特殊落下）では、横方向の空中制御が残る**。
効きは弱くなるが、崖へ向けて寄せることができる。これがあるから
「上Bが少し届かなくても、そのあと横に寄せて崖を掴む」という復帰が成立する。
このゲームは制御が完全にゼロなので、上必殺を出す位置を1pxでも間違えたら
そこで詰みになる。

### CPU側の関連する死にコード

`js/cpu-ai.js:520` 付近、`_recoveryIntent` の先頭：

```js
// 上必殺を使い切っていたら、あとは横に寄せることしかできない
if (self.helpless) {
  input.left = toward < 0; input.right = toward > 0; input.stickX = toward;
  return input;
}
```

「横に寄せる」つもりで入力を作っているが、`applyInput` が捨てるので
**何も起きていない**。修正1を入れれば、このコードが初めて意図どおり動く。

## 3. 直すこと

### 修正1（本命）— しりもち落下でも横方向の空中制御を残す

`js/fighter.js:436` の helpless 分岐を、
「何もできない」から「**横移動だけできる**」に変える。

```js
    // 行動不能（上B使用後など）：着地するまで攻撃もジャンプも回避もできない。
    // ただし本家のしりもち落下と同じく、横方向の空中制御だけは残す。
    // ここで完全に操作不能にすると空気抵抗すら効かず、上必殺を出した瞬間の
    // 横速度のまま等速で流され続ける（実測：外向き速度-3のまま120フレームで
    // 360px流され、内側を入れても速度は-3から変わらなかった）。
    // これだと上必殺を出す位置を少しでも間違えた時点で詰みになる。
    if (this.helpless) {
      if (!this.onGround) { this._applyHelplessDrift(input); return; }
      this.helpless = false;
    }
```

`_applyHelplessDrift(input)` は、通常の空中移動（`js/fighter.js:568` 付近の
`else` ブロック）と**同じ式**を使い、加速度と最高速度に
`CONFIG.HELPLESS_AIR_CONTROL` を掛けたものにする。

```js
  // しりもち落下中の横移動。通常の空中制御を弱めたもの。
  // 入力が無い時の空気抵抗もここで掛ける（これが無いと外向きの速度が
  // 永久に減らない）。ジャンプ・攻撃・回避・急降下はできないままにする。
  _applyHelplessDrift(input) {
    const stickX = input.stickX || 0;
    const absX = Math.abs(stickX);
    const control = CONFIG.HELPLESS_AIR_CONTROL;
    const airMax = Physics.computeMoveSpeed(this.stats.evasion, true)
      * CONFIG.AIR_MAX_SPEED_RATIO * control;
    if (absX < CONFIG.WALK_DEADZONE) {
      this.vx *= CONFIG.AIR_FRICTION;
      return;
    }
    const dir = Math.sign(stickX);
    const speed = Math.abs(this.vx);
    if (speed > airMax && Math.sign(this.vx) === dir) {
      this.vx *= CONFIG.AIR_FRICTION;
      return;
    }
    const target = dir * airMax * Math.min(1, absX / CONFIG.DASH_TILT_THRESHOLD);
    const accel = CONFIG.AIR_ACCEL * control * absX;
    if (this.vx < target) this.vx = Math.min(target, this.vx + accel);
    else if (this.vx > target) this.vx = Math.max(target, this.vx - accel);
  }
```

`js/config.js` に追加：

```js
  // しりもち落下（上必殺後）の横移動の効き。本家でも操作は残るが弱くなる。
  // 1.0にすると上必殺のリスクが無くなるので、通常の6割にとどめる。
  HELPLESS_AIR_CONTROL: 0.6,
```

**守ること**
- helpless 中に**ジャンプ・攻撃・必殺・ガード・回避・急降下ができない**性質は
  そのまま残す。横移動だけを許可する
- 着地したら helpless が解除される既存の流れ（`:439`）を壊さない
- 崖を掴んだ時の解除（`releaseFromLedge` 周辺の `helpless = false`）も壊さない
- `_applyHelplessDrift` は `applyInput` の中から呼ぶこと。
  `update()` 側に置くと、ヒットストップやポーズ中にも動いてしまう

### 修正2 — CPUの復帰目標を、崖を掴める高さに合わせる

修正1を入れると `_recoveryIntent` の helpless 分岐（`js/cpu-ai.js:520`）が
初めて機能する。ここは既に「近い方の崖へ向けて横を入れる」形になっているので、
**コードの変更は不要**。ただし動作確認はすること。

### 修正3 — 追撃の許可距離を測り直す

`_pursuitLimit()`（`js/cpu-ai.js:183`）の 311 / 547 / 90 は、
**helpless で一切動けない前提で測った値**。修正1で復帰性能が上がるので、
必ず測り直して更新すること。測り方は既存コメント（`:162-177`）と同じ手順で、
「崖の外◯pxに、空中ジャンプ◯回残しで置き、`_recoveryIntent` だけを回して
戻れるか」を20px刻みで探す。

## 4. 検証手順

### 4-1. helpless の横移動そのものを測る

`new Fighter(...)` を直接生成する簡易な確認でよい**この項目だけは**。
当たり判定もCPUの判断も関係しないため。

- 崖の外150px・`helpless = true`・`vx = -3` で置き、内側を60フレーム入力
- **修正前：120フレームで360px外へ流され、速度-3のまま変わらない**
- 修正後：速度が0を通過して内側へ向き、内側へ戻り始めること
- 通常の空中（helplessでない）の横移動が**変わっていない**こと
  （60フレームで250px・速度5.53が変わらないこと）

### 4-2. 自滅の数は必ず実バトルで測る

**簡易ハーネスで自滅率を判断しないこと。** 当たり判定もキャラ固有値も
無いため実ゲームと挙動が違う。`docs/cpu-selfdestruct-plan.md` §4-2 と
`docs/cpu-selfdestruct-plan2.md` §5-2 の手順で、
**両者をAIで動かした対戦**（`InputManager.getPlayer1Input` を差し替え）を回す。

四大大会3種＋レジェンド杯 × 8シード以上 × 各90秒、1P側のレベルは7と9の両方。

| 指標 | 5cb532d 時点の実測 | 合格ライン |
|---|---|---|
| CPU自滅（1P Lv7） | 11 | **2以下** |
| CPU自滅（1P Lv9） | 8 | **2以下** |
| CPU崖越え（Lv7 / Lv9） | 32 / 50 | 半分以下 |
| 技発生 | — | 修正前の9割以上（弱腰になっていない確認） |

**修正前の数値も自分で取り直すこと。** 上の数値をそのまま比較対象に
しないこと。`git worktree add` で修正前のコミットを別ディレクトリに出し、
別ポートで配信して同じスクリプトを両方に当てる。

### 4-3. 壊していないことの確認

- **プレイヤーの復帰が簡単になりすぎていないか。** 上必殺を出したあと
  横に寄せられるようになるので、崖から遠い位置でも戻れるようになる。
  `HELPLESS_AIR_CONTROL` が高すぎると上必殺のリスクが消える。
  0.6で「わずかに寄せられる」程度か、実際に触って確認すること
- 通常のCPU戦（レベル1〜9・既定ステータス）で自滅が増えていないこと
- 修行5コース（`js/practice.js`）が壊れていないこと。
  カウレア火山は上必殺を使う場面があるので特に確認

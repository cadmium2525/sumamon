# マスモンのスキン（色変更）設計メモ

「虹彩の染色セット」でマスモンの色を自由に変えられるようにするための設計。
打ち合わせで決まった内容をまとめたもので、実装はまだ入っていない。

## 何を作るか

- モンスターの色をパーツごとに塗り替えられる。
- プリセット（本家スマブラのようなカラーバリエーション）＋自由色。
- 編集画面はズーム対応。細かい所も指定できる。

## 方式：色グループ置換

領域（マスク画像）ではなく **色** で置き換える。

1. 立ち絵の色を色相でまとめ、8個前後の「色グループ」を自動抽出する。
2. グループごとに新しい色を指定する。
3. 置き換えは HSL の **H（色相）と S（彩度）だけを差し替え、L（明度）は元のまま**。
   陰影とハイライトが保たれ、べた塗りにならない。

### なぜこの方式か

- **専用モーションにも自動で効く。** 色で置き換えるため、待機・ジャンプ・崖つかまり、
  そして今後 Layer 1 で追加する専用モーションにも、コマごとの作業ゼロで反映される。
- **保存データが小さい。**「グループ→色」の対応表だけ（数十バイト）。
  Firestore に載り、マルチ対戦の相手にも同期できる。
- ベースモンスターの定義（data/fighters.json）は一切変えない。マスモン側の属性になる。

### 実測（この方式が成立する根拠）

| | 実際の色数 | 色相でまとめた数 | 上位8グループの占有率 |
|---|---|---|---|
| イルミネ 待機 | 17,620 | 52 | 約80%（紫系だけで6割） |
| デュラハン | 47,803 | 61 | 約81%（白銀3割・金3割） |

生の色数は数万あるが、色相でまとめると 50〜60。しかも上位8つで8割を占める。
「マント」「装飾」「肌」といったパーツ単位のまとまりが色として実在している。

## 決まった仕様

### 塗り分けの粒度：自動抽出グループ ＋ 範囲指定での分割

自動抽出だけだと、別パーツが同じ色（例：目と靴が同じ黒）の場合に一緒に変わってしまう。
「この範囲だけ別グループにする」を入れて分離できるようにする。

- 分割情報は矩形などの軽い形で持ち、保存データが画像サイズにならないようにする。
- ピクセル単位の自由塗りは採らない（保存容量とマルチ同期が破綻するため）。

### 染色セットの消費：プリセットは無料・自由色は消費

- こちらで用意する固定カラーはいつでも無料で切り替えられる。
- オリジナルカラーを作る時だけ「虹彩の染色セット」を消費する。
- 確定前のプレビューは無料。

### 反映範囲：すべて

- バトル中のスプライト（全モーション）
- HUD・ストックアイコン
- ファイター選択・マスモン管理画面
- マルチ対戦の相手側にも同期

同じ塗り替え関数を通せば全部そろう。

## 実装の順序（案）

1. **塗り替えエンジン**（新規 js/skin.js）
   - 色グループの抽出、H/S 置換、コマ画像の再描画とキャッシュ。
   - 変換表はピクセル色をキーにしたキャッシュで持つ。バトル開始前に1回だけ実行。
     イルミネ全20コマで数十ms程度の見込み。実行中の負荷はゼロ。
2. **保存とデータ**
   - `masmon.skin = { groups: [...], splits: [...] }` を MasmonStore へ。
   - マルチのロースター送信にも載せる（js/multiplayer.js）。
3. **表示側の差し替え**
   - Fighter のスプライト読み込みで塗り替え済みキャンバスを使う。
     パーツ分割・武器レイヤーは塗り替え後の絵を切るだけなので順序に注意。
   - HUD／ストックアイコン／選択・管理画面も同じ関数を通す。
4. **編集画面**（マスモン管理から開く）
   - ズーム・パン付きのキャンバス。タップした位置の色グループを選択。
   - パレット（基本色＋自由選択）、プリセット一覧、範囲指定での分割。
5. **プリセット**
   - モンスターごとに固定カラーを用意する。

## 注意点

- パーツ分割（v1.01）と武器レイヤー（v1.00）は、**塗り替えたあとの絵**から切り出すこと。
  順序を逆にすると元の色のまま切り出されてしまう。
- 自動モーション（v0.98）は変形だけなので影響を受けない。
- 塗り替えた結果もキャッシュしないと、画面を移動するたびに再計算になる。
  （fighterKey + スキンの内容）をキーにしたキャッシュを持つ。
